# HoneyForge — Roadmap до коммерческого продукта

**Цель:** превратить HoneyForge из рабочего прототипа в **полноценный продукт корпоративного
уровня**, который продаётся по лицензии (on-prem/SaaS) и выдерживает проверку опытным
пентестером. Приоритет — **функционал, глубина и реальность**, а не простота интерфейса.

> Статус-кво: светлая/тёмная тема, дизайн-система, карта сети (React Flow), дашборд с real-time
> событиями, конструктор ловушек (tcp-banner / redis / honeytoken-http / ssh-high-interaction),
> боевое развёртывание на Linux через Docker Swarm, mTLS, маскировка агента (node-metrics).
> Этого **мало** для продажи — ниже план, что добавить.

---

## Принципы
1. **Никакой «картонности».** Всё, что видит пентестер, должно быть настоящим: реальные
   протоколы, реальная детекция, реальное развёртывание.
2. **Функционал > косметика.** UI уже на уровне; вкладываемся в возможности.
3. **Глубина протоколов и endpoint-deception** — главный дифференциатор.
4. **Explainability** — каждое событие объяснимо и ложится в стандарты (MITRE ATT&CK / ФСТЭК).
5. **Enterprise-ready** — мультиарендность, роли, аудит, отчёты, интеграции, лицензирование.

---

## Фаза 0 — «Не прототип» (фундамент под демо)
Цель: пентестер щупает реальное, без заглушек.
- [ ] Убрать mock-ограничения в проде; явный боевой режим.
- [ ] Гайд развёртывания на чистом Linux-сервере (одна команда / ansible), self-check.
- [ ] Health/observability: статусы всех ловушек, агентов, очередей; алерты на сбой.
- [ ] Нагрузочная проверка: десятки ловушек, тысячи событий — без деградации.
- [ ] Хронология аудита действий оператора (кто что развернул/остановил).

## Фаза 1 — Конструктор цепочек и ветвлений ⭐ (ключевая просьба)
Цель: не отдельные ловушки, а **ложная инфраструктура с attack-path**.
- [ ] Модель **цепочки**: связи ловушка→ловушка, условия перехода (порт/креды/действие).
- [ ] **Ветвление** (lateral movement): из одной ловушки атакующий «проваливается» в следующую
      (например, нашёл креды в honeytoken → они подходят к ssh-ловушке → дальше к «файловому серверу»).
- [ ] Визуальный редактор на React Flow: узлы-ловушки, рёбра-переходы, условия на рёбрах,
      шаблоны готовых сценариев (DMZ, внутренняя сеть, АРМ пользователя).
- [ ] Исполнение цепочки на бэкенде: связанные креды/токены, согласованная топология.
- [ ] Реконструкция **пути атакующего** по IP/сессии в таймлайн kill-chain.

## Фаза 2 — Глубина протоколов и endpoint-deception
Цель: упор на уязвимости протоколов и рабочих станций пользователей.
- [ ] Расширить ловушки: SMB, RDP, HTTP(S)-приложение с ложными уязвимостями, SQL/БД, FTP, SNMP.
- [ ] Реалистичные баннеры/версии/поведение (развитие слоя `camouflage`): fingerprint как у боевых.
- [ ] **Endpoint-приманки**: ложные креды/файлы/сетевые шары под АРМ пользователей, honeytoken-ы
      в документах, ловушки для кражи учёток.
- [ ] Перехват и разбор payload по протоколам (не только сырой дамп): команды, эксплойт-попытки.
- [ ] Тонкая настройка конфигов протоколов во фронте (не дефолты, а реальные параметры).

## Фаза 3 — AI-слой (нейросеть в конструкторе и аналитике)
Цель: умный помощник + онлайн-классификация атак.
- [ ] **AI-ассистент конструктора**: по описанию инфраструктуры покупателя генерирует/рекомендует
      цепочку ловушек под его сеть и модель угроз.
- [ ] **Онлайн-классификация техник** атакующего → **MITRE ATT&CK** (T####) в реальном времени.
- [ ] Объяснимые отчёты: что сделал атакующий, какие техники, рекомендации по защите.
- [ ] Приоритет on-prem/локальная модель (изоляция данных заказчика); облачная — опционально.

## Фаза 4 — Enterprise и лицензирование
Цель: продукт готов к продаже и внедрению у корпоративных заказчиков.
- [ ] **Мультиарендность** (несколько организаций/проектов), изоляция данных.
- [ ] **RBAC** (роли: админ/оператор/наблюдатель/аудитор) + полный аудит.
- [ ] **Лицензирование**: ключи, лимиты по тарифу, срок, офлайн-активация для on-prem.
- [ ] **Интеграции**: экспорт событий в SIEM/SOAR (syslog/CEF/webhook), API для автоматизации.
- [ ] **Отчёты**: PDF/JSON, маппинг на стандарты (MITRE ATT&CK, ФСТЭК/ISO — уточнить).
- [ ] Мультиязычность (RU/EN), документация, white-label под заказчика.

---

## Приоритет к ближайшему демо (для пентестера)
1. **Фаза 1** (конструктор цепочек/ветвлений) — самое заметное и прямо запрошенное.
2. **Реконструкция пути атакующего** (из Фазы 1) — показывает детекцию, собирается из текущих событий.
3. **+1 глубокий протокол** из Фазы 2 (напр. SMB или HTTP-app с реальным разбором) — «не картон».
4. **ATT&CK-маппинг** (из Фазы 3, без полноценного AI) — быстро повышает экспертную ценность.

---

## Открытые вопросы (нужны решения)
- **Стандарты** для отчётов/комплаенса: ФСТЭК? MITRE ATT&CK? ISO 27001? PCI-DSS?
- **AI**: роль (генерация цепочек / классификация атак / оба) и провайдер (локальная LLM vs облако).
- **Мой скоуп**: full-stack или фронт + ТЗ бэкенд-коллегам? (Фазы 1–3 требуют бэкенда.)
- **Модель поставки**: on-prem по лицензии, SaaS, или гибрид — влияет на лицензирование и AI.

## Допущения (поправь, если не так)
- Деплой — Linux-сервер, Docker Swarm (как сейчас).
- Фронт остаётся React+Vite+TS+React Flow; бэкенд — Go.
- Первый покупатель/оценщик — опытный пентестер → упор на реальность и глубину.
