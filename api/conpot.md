# Conpot ICS/SCADA

`conpot/1` работает через существующие профили, ловушки и команды
`apply_config`, `start`, `stop`. Один экземпляр эмулирует один протокол.
Новые REST-маршруты и права доступа не добавляются. Профили создаёт
администратор, управление ловушкой и чтение событий используют обычные
проверки организации и полномочий.

| `services[0].protocol` | Протокол | Транспорт | Обычный порт |
|---|---|---|---|
| `modbus` | Modbus TCP | TCP | 502 |
| `s7comm` | Siemens S7 | TCP | 102 |
| `snmp` | SNMP | UDP | 161 |
| `bacnet` | BACnet/IP | UDP | 47808 |
| `enip` | EtherNet/IP | TCP | 44818 |

Порт можно изменить. Для разных протоколов создавайте отдельные ловушки:
это сохраняет независимое управление, изоляцию и атрибуцию событий.
Текущая проверка занятости резервирует номер порта целиком, включая оба
транспорта. BACnet отвечает на unicast-запросы; исходящие broadcast-анонсы
и автоматический поиск других устройств отключены политикой изоляции.

Пример `config` для `POST /api/profiles`:

```json
{
  "services": [{ "name": "plc", "port": 1502, "protocol": "modbus" }],
  "session": { "max_connections": 16, "max_seconds": 300 },
  "management": {
    "heartbeat_interval_seconds": 5,
    "telemetry_flush_interval_ms": 500
  }
}
```

Конфигурация проверяется по дескриптору из каталога. Допустимы 1–32 активных
сеанса и длительность 5–300 секунд. TCP-соединения принудительно закрываются
по сроку; UDP-сеанс объединяет обращения одного адреса/порта и закрывается
после 5 секунд без событий либо по максимальной длительности. JSON с
путями к шаблонам, исполняемыми выражениями, экспортёрами и неизвестными
полями отклоняется. Используется стандартная личность устройства из
зафиксированного upstream-шаблона; произвольные личности пока не настраиваются.

События: `service.connection_opened`, `service.action`,
`service.connection_closed`. `service.action.input` содержит ограниченное
описание запроса/ответа Conpot, `outcome` — `unknown`; это наблюдение
протокола, а не доказательство успешного исполнения команды. `truncated`
показывает усечение. Сохраняется максимум 1024 UTF-8 байта текста события.
Счётчики отражают известные байты запросов; для структурированных SNMP
наблюдений длина исходного UDP-пакета неизвестна и не выдумывается.
Полный pcap и воспроизведение сессии для этого типа не предоставляются.

Телеметрия не открывает listener в сети приманки. Conpot передаёт наблюдения
через анонимные pipe в Go-обёртку, которая использует существующий TLS-pipe
агента. ACK выдаётся после подтверждения записи в журнал агента. Очередь
ограничена 64 наблюдениями; ошибка доставки или переполнение останавливают
runtime. Журнал Redis и подтверждения backend работают как у других типов.
Содержимое запросов не дублируется в Docker-логи.

Контейнер приманки не получает Docker socket, управляющие секреты, адрес
backend или Redis. Python-процесс получает только конфигурацию протокола.
Файловая система read-only; `/run/conpot` — ограниченный tmpfs для MIB-кеша.
Worker запускается с непривилегированным UID, без capabilities после
установки firewall. Исходящие IPv4-пакеты разрешены только как ответы на
входящие соединения/датаграммы; IPv6 и DNS-выход отключены. Conpot CLI,
LogWorker, hpfeeds, syslog и определение публичного IP не запускаются;
загрузка MIB по HTTP отключена.

Это скрывает сетевой канал управления от клиента эмулируемого сервиса.
Полная невидимость при захвате Python-процесса или Docker-хоста не
гарантируется; ответные пакеты сохраняют особенности upstream-эмуляции.

## Запуск и проверка

Образ `honeyforge/conpot-decoy:local` собирается сервисом
`decoy-conpot-image` в основном Compose. Для своего реестра задайте
`DECOY_CONPOT_IMAGE`; образ должен присутствовать на выбранном Swarm-узле.
Conpot зафиксирован на коммите
`839f892a94c5dc9ced67d5c2f6a4e618a658a050`, Python-зависимости — его
`uv.lock`. Лицензия upstream находится в образе в
`/usr/share/doc/conpot/LICENSE.txt`.

В панели выберите **Conpot ICS/SCADA**, протокол и порт; дождитесь `online`
и `running`. Для Modbus проверьте чтение coils, для S7 — COTP handshake,
для SNMP — GET `sysDescr.0`, для BACnet — unicast ReadProperty, для
EtherNet/IP — ListIdentity. Наблюдения доступны в обычном разделе событий.

Нативная проверка всех пяти движков (без проверки Docker/firewall):

```sh
HF_PYTHON=/path/to/python-with-pinned-conpot TEST_CONPOT_RUNTIME=1 \
  go test -tags=integration ./internal/decoys/conpottrap -run TestRealConpotProtocols
```

Команда выполняется из `src/backend`. Проверки очереди и границ адаптера:

```sh
python src/backend/internal/decoys/conpottrap/scripts/telemetry_test.py
```

Для проверки изоляции работающего worker на Linux используйте
`deploy/verify-isolation.sh CONTAINER_ID` и Docker-тест с
`TEST_CONPOT_DOCKER=1`, описанный в тестовом файле.
