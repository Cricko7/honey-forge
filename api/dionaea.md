# Dionaea

`dionaea/1` использует существующие профили, ловушки, события и команды
`apply_config`, `start`, `stop`. Действуют существующие права организации.
Один экземпляр слушает один TCP-порт; протокол и порт выбираются в панели.

| `services[0].protocol` | Сервис | Обычный порт |
|---|---|---|
| `smb` | SMB | 445 |
| `mssql` | MSSQL | 1433 |
| `mysql` | MySQL | 3306 |
| `mqtt` | MQTT | 1883 |
| `http` | HTTP | 80 |
| `memcache` | Memcached | 11211 |

```json
{
  "services": [{ "name": "files", "port": 1445, "protocol": "smb" }],
  "session": { "max_connections": 16, "max_seconds": 300 },
  "management": { "heartbeat_interval_seconds": 5, "telemetry_flush_interval_ms": 500 }
}
```

Допускается 1–32 одновременных соединения, длительность сессии 5–300 секунд.
Бездействующее соединение закрывается через меньшую из величин: 30 секунд и
`max_seconds`. Входной буфер ограничен 8192 байтами, входящий и исходящий
трафик соединения — 1 МиБ каждый. Неизвестные поля, произвольные пути,
обработчики, экспортеры и нативные конфиги отклоняются. Используются
стандартные ответы зафиксированного upstream; личность сервиса пока не настраивается.

## События

`service.connection_opened`, `service.action`, `service.auth_attempt`,
`service.connection_closed`. Атрибуция сервиса, порта, типа и ревизии берётся
из конфигурации агента. IP и исходный порт принадлежат принятому соединению.
Последовательность событий отдельная для каждой сессии.

`service.action.input` содержит hex первых 512 новых входящих байтов,
максимум 1024 символа; `truncated` отмечает усечение. Повторно переданный
парсеру неполный буфер не увеличивает счётчики. Это наблюдение входных
данных, а не подтверждение выполнения команды: `outcome` равен `unknown`.

Попытки входа фиксируются по нативным событиям MSSQL, MySQL и MQTT.
Для MySQL доступен логин, `password` равен `null`: upstream не передаёт
аутентификационный ответ. SMB фиксируется через обычные события запросов.
Поля учётных данных ограничены 1024 UTF-8 байтами каждое; `received_bytes`
у события входа равен нулю, поскольку байты уже учтены в `service.action`.
Результат входа не выдумывается (`unknown`). Полного pcap и воспроизведения нет.

## Изоляция и телеметрия

Нативный движок получает только конфигурацию сервиса и локальные pipe.
У него нет адреса backend/Redis, управляющих токенов или Docker socket.
Наблюдения идут через отдельный FD 3 в Go-обёртку и существующий TLS-pipe
агента. ACK выдаётся после записи события в журнал агента. Очередь ограничена
64 событиями; переполнение или сбой доставки останавливает движок.
Нативные stdout/stderr и журналы направлены в `/dev/null`.

Включён только Python-модуль с нашим адаптером. Сетевые загрузчики, curl,
эмуляция shellcode, packet capture, стандартные ihandlers, hpfeeds и другие
экспортеры не запускаются. HTTP использует статический корень без шаблонов
и SOAP; MySQL — SQLite в памяти. Пассивно принятые образцы могут временно
попасть в `/run/dionaea`: это tmpfs на 8 МиБ с `noexec`, данные не экспортируются.

Worker работает под UID 65532, с read-only корнем, лимитами памяти/процессов
и без capabilities после настройки firewall. Исходящий IPv4 разрешён только
как ответ на входящее соединение; IPv6 и исходящий DNS отключены. Телеметрия
не открывает сетевой listener в сегменте приманки. Компрометация процесса
или Docker-хоста может обнаружить адаптер; абсолютная невидимость не гарантируется.

FTP, TFTP, SIP и другие протоколы с дополнительными портами пока не входят
в интеграцию: они требуют отдельной настройки сетевой изоляции.

## Сборка и проверки

Основной Compose собирает `decoy-dionaea-image`. Можно задать
`DECOY_DIONAEA_IMAGE`; образ должен быть доступен на выбранном Swarm-узле.
Используется [DinoTools/dionaea](https://github.com/DinoTools/dionaea) на коммите
`4e459f1b672a5b4c1e8335c0bff1b93738019215`, Debian bookworm / Python 3.11.
Лицензия upstream сохранена в `/opt/dionaea/share/doc/dionaea/LICENSE`.
Две проверяемые правки исходников ограничивают пул четырьмя потоками и
делают пути модулей абсолютными. При сборке образа проверяются ответы
всех шести протоколов, закрытие всех сессий и остановка при сбое журнала
под UID 65532.

```sh
docker compose -f docker-compose.real.yml build decoy-dionaea-image
```

Проверка firewall, границ контейнера и доставки через TLS-pipe (из `src/backend`, Linux Docker):

```sh
TEST_DIONAEA_DOCKER=1 DECOY_DIONAEA_IMAGE=honeyforge/dionaea-decoy:local \
  go test -tags=integration ./internal/agent -run TestDionaeaDockerIsolation
```

В панели выберите **Dionaea**, протокол и порт; после `online` / `running`
подключитесь соответствующим клиентом. События появятся в обычной истории ловушки.
