# Проверка безопасности и стабильности — 15 октября 2026

Выполнены два прохода по исходникам. Первый: аутентификация, права,
границы организаций, обработка недоверенного ввода, сетевые и файловые операции.
Второй: повторные проверки после очередей, смена сессии, отказ телеметрии,
отложенные запросы и безопасное отображение данных. Это выборочная проверка
кода и локальных сценариев, без проверки развёрнутого стенда.

## Исправления

| Проблема | Последствие | Исправление и подтверждение |
| --- | --- | --- |
| HTTP-телеметрия ограничивала путь по символам, хотя JSON увеличивает его размер | Запрос с длинным экранируемым путём и телом мог превысить лимит локального канала 16 КиБ и остановить HTTP runtime | Путь в телеметрии ограничен 2048 символами и 4096 байтами после JSON/HTML-экранирования. Реальная маршрутизация использует полный путь. Живой TCP-тест воспроизвёл остановку до исправления; после него проходят ASCII, не-ASCII и HTML-символы, сохраняется захват тела, следующий нормальный запрос успешен. Ограничение применяется также к HTTP pipeline. |
| Очередь raw traffic теряла связь с исходной сессией | Уже принятые копии могли доставляться после удаления связи, отзыва или замены источника | Элемент очереди сохраняет сессию источника. Перед отправкой проверяются её актуальность, реквизиты и текущая связь; затем отдельно проверяется получатель. Три сценария отзыва воспроизводились падающими WSS-тестами. Также проверена двусторонняя доставка без совместного удержания блокировок источника и получателя. |
| Общий frontend cache переживал смену аккаунта в другой вкладке | Панель нового аккаунта могла кратковременно показывать старые детали, профили или код приглашения | Для каждой организации, пользователя и браузерной сессии создаётся отдельный cache. Проверка сессии остаётся общей. Запоздалые запросы, мутации и сообщения сохраняют ссылку только на прежний cache. 401/403 закрывает приватную область; сетевой сбой скрывает содержимое и сохраняет её cache для восстановления. Регрессия воспроизвела показ старого кода приглашения до исправления. |
| Уведомления конструктора вставляли названия и сообщения через innerHTML | Сохранённая HTML-разметка могла выполняться в браузере оператора | Сообщения выводятся через textContent; списки создаются как UL/LI с текстовыми значениями. Проверены названия, ошибки сервера, поля списка, замена уведомлений и таймеры. |

Форматы ресурсов и опубликованные immutable-схемы каталога сохранены.
Уточнения телеметрии и повторных проверок raw traffic внесены в OpenAPI.
Зависимости в рамках этой проверки не обновлялись; изменения не развёрнуты.

## Успешные проверки

- `go fmt ./...`, `go vet ./...`, `go test ./...`, `go build ./...` из `src/backend`.
  Для Python-сценариев задан `HF_PYTHON` на рабочий Python 3.12; системный
  Windows alias `python3` запускать интерпретатор не мог.
- Фронтенд: 94 теста, `tsc -b`, production build Vite.
- Конструктор: 19 тестов integration/http_builder/http_pipeline/runtime_stream
  с локальными fake API, без внешнего стенда.
- Python HTTP scripts: 12 тестов движка и локального сервера.
- `govulncheck`: 0 уязвимостей в вызываемом коде и импортируемых пакетах;
  одна запись относится к модулю, чей уязвимый код не вызывается.
- `git diff --check`.

## Ограничения

- `go test -race ./...` запускался с `CGO_ENABLED=1`, но сборка остановилась:
  C-компилятор GCC отсутствует. Это не успешная проверка гонок.
- Два дополнительных deployment-теста (`deploy.nginx.test_constructor` и
  `deploy.test_release_cleanup`) упали при создании symlink с WinError 1314.
  Остальные тесты этого запуска прошли. Эти два сценария требуют подходящего
  Windows-окружения или Linux.
- PostgreSQL/Kafka/Redis integration suite, Docker/Swarm и Linux sandbox
  в этой сессии не запускались: требуемой инфраструктуры и тестовых настроек нет.
- Повторная проверка источника/связи выполняется перед доставкой, но не образует
  единую атомарную операцию между PostgreSQL и записью в сокет. Пакет, уже
  прошедший проверку одновременно с отзывом, может успеть уйти.
- Тесты frontend cache используют SSR и QueryClient; переходы в настоящем
  браузере и React StrictMode проверены по коду, без браузерного E2E-прогона.
