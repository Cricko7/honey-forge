# Docker-деплой на несколько узлов Swarm

CI/CD загружает архив образов на manager, затем запускает `sync-images.sh`.
До обновления приложения скрипт доставляет тот же архив на остальные узлы
через существующую overlay-сеть `hf-mgmt` и проверяет SHA-256 архива и ID
каждого образа. Registry и отдельные SSH-ключи для workers не нужны.

Раздача выполняется временным сервисом без опубликованного порта. В архиве
только образы приложения; SMTP и другие серверные настройки туда не входят.
Архив передаётся по HTTP внутри управляющей сети; его целостность проверяется
по хешу, переданному через управляющий канал Swarm, до вызова `docker load`.

На каждом узле кратковременно запускается доверенное задание с Docker socket,
которое загружает и проверяет образы. Используется уже запущенный supervisor
HoneyForge. На пустом узле используется `docker:27.5.1-cli`: образ должен
быть заранее загружен либо доступен из Docker Hub. Для него можно задать
`DEPLOY_IMAGE_LOADER_IMAGE` в окружении вызова скрипта.

Все узлы должны быть `Ready/Active`, иметь одинаковую архитектуру, свободное
место для архива и образов и рабочую связь в `hf-mgmt`. При ошибке загрузки,
неверном хеше или недоступности узла переключение приложения не начинается.
Временные сервисы удаляются и при успехе, и при ошибке. Узлы, сети и тома
скрипт не удаляет, Docker не перезапускает.

После доставки образов CI/CD обновляет приложение и существующие сервисы
ловушек с сохранением их placement constraints. Новые ловушки используют
образы текущего релиза. Настройки SMTP по-прежнему берутся из закрытого
`/etc/honey-forge/production.env` на manager.

Если новый узел подключён после деплоя, администратор может загрузить на него
образы текущего релиза с manager:

```bash
cd /opt/honeyforge/current
bash sync-images.sh release.env images.tar.gz "manual-$(date +%s)"
```

Проверка дистрибуции и синтаксиса не заменяет успешный CI/CD-деплой и проверку
запуска ловушки на worker.
