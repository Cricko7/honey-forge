# Автоматическое размещение приманок

Основной `docker-compose.real.yml` собирает два изолированных образа приманок,
запускает оркестратор и включает автоматическое развертывание в API. Дополнительный
Compose-файл и ручное создание Swarm или сети не нужны.

```sh
docker compose -f docker-compose.real.yml up --build -d
```

Используйте обычные `.env` и сертификат из [REAL-STACK.md](../../REAL-STACK.md).
Оркестратор сам включает одноузловой Docker Swarm, создаёт overlay-сеть и
подключает к ней API и Redis. После `POST /api/traps` он выдаёт реквизиты агенту,
создаёт Swarm service, ставит команды `apply_config` и `start`. Агент открывает
порт из профиля и передаёт события через существующий WSS/Redis-поток. Ответ
`POST` остаётся `201`: развертывание асинхронное; состояние видно через
`GET /api/traps/{id}` и `GET /api/traps/{id}/commands`.

На одном хосте Swarm размещает контейнер там же. Если в Swarm есть другие узлы,
планировщик выбирает подходящий по ресурсам и доступности опубликованного порта.
Каждой ловушке соответствует отдельный контейнер без Docker socket. Токен агента,
адрес Redis и сертификат CA передаются через Docker secrets; процесс приманки
работает без доступа к ним. Локальный Redis из основного Compose хранит журналы
в постоянном томе.

Для нескольких хостов присоедините их к Swarm. Образы должны быть доступны на
каждом узле: задайте `DECOY_TCP_IMAGE` и `DECOY_REDIS_IMAGE` как теги вашего
реестра и опубликуйте собранные образы. API и Redis остаются на основном хосте,
а агенты подключаются к ним через overlay-сеть. При сбое узла Swarm переносит
задачу на другой узел с доступным портом.

Операторские команды `stop` и `start` после первоначального автоматического
запуска остаются доступными. Изменение профиля требует явного `apply_config`.
Существующие ловушки остаются в ручном режиме. Выдача и отзыв реквизитов агента
для новых управляемых ловушек возвращают `409 agent_credentials_managed`.

Диагностика:

```sh
docker compose -f docker-compose.real.yml logs orchestrator
docker service ls --filter label=honeyforge.trap
docker service ps --no-trunc hf-trap-<TRAP_ID>
```
