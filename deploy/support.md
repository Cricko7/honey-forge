# SMTP в Docker-деплое

CI/CD включает `compose.support.yml` в каждый новый релиз. Он передаёт API
шесть SMTP-переменных из закрытого `/etc/honey-forge/production.env` на сервере.
Аккаунт и пароль не входят в Git, Docker-образ, архив релиза или GitHub Actions Secrets.
При откате используются настройки сервера; старые релизы без этого файла
продолжают разворачиваться по прежней схеме.

Добавьте в серверный `production.env`:

```dotenv
SUPPORT_SMTP_HOST=smtp.gmail.com
SUPPORT_SMTP_PORT=587
SUPPORT_SMTP_SECURITY=starttls
SUPPORT_SMTP_USERNAME=YOUR_SENDER_ADDRESS
SUPPORT_SMTP_PASSWORD=YOUR_APP_PASSWORD
SUPPORT_SMTP_FROM=YOUR_SENDER_ADDRESS
```

Для Gmail нужен пароль приложения. Заполняйте файл непосредственно на сервере
через защищённое подключение. Ограничьте доступ к файлу пользователем деплоя
(`chmod 600` при соответствующем владельце). Не выводите содержимое файла,
полный результат `docker compose config` или окружение контейнера в логи CI.

После записи значений следующий успешный CI/CD-деплой передаст их API.
Настройки сохраняются между релизами. Если все шесть переменных отсутствуют
или пусты, API работает с отключённой отправкой; форма возвращает 503.
Частично заполненная конфигурация останавливает запуск API с ошибкой.

Проверять отправку нужно на развёрнутом сайте, через раздел «Техподдержка».
Деморежим фронтенда письма не отправляет. Сообщение об успехе означает принятие
письма SMTP-сервером; конечную доставку проверяйте в почтовом ящике поддержки.
