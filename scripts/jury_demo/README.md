# Живая демонстрация HoneyForge для жюри

Запустите **start.cmd** двойным щелчком или из PowerShell:

```powershell
.\start.cmd
```

Нужен Python 3.11+. На этом компьютере запускатель также находит Python, поставляемый с Codex. При первом запуске установит две зависимости для SSH и WebSocket.

Введите `Site` (Enter оставляет адрес HoneyForge), затем **Login** и **Password**. Пароль вводится скрыто. Учётные данные, cookie и CSRF остаются в памяти процесса. Для связей сети нужна роль администратора.

Каждый следующий шаг выполняется **только после Enter**. Ctrl+C завершает сценарий. Дождитесь результата текущего действия, затем переходите дальше.

## Что показывать жюри

В браузере войдите в ту же организацию. Скрипт откроет `/app/network`; вход в браузере отдельный, пароль в браузер скрипт не передаёт. Держите рядом журнал событий. Для просмотра схем откройте «Конструктор ловушек» и выберите схемы с текущей меткой `Жюри …`.

1. Создание восьми обычных ловушек: **Conpot Modbus, Conpot S7, Dionaea HTTP, Dionaea Memcached, два TCP-сервиса, Redis и SSH**. Скрипт ждёт запуска каждой.
2. Создание двух новых HTTP-ловушек из блоков конструктора: **Портал — 30 блоков / 43 соединения**, **Шлюз — 28 / 40**. Есть разбор JSON, обязательные поля, преобразования, условия, выбор операции, сессия, три ветки, объединение результатов, внутренние вызовы, события и обработка ошибок.
3. Создание стрелки **Портал → Шлюз** в сети. Передача JSON использует настоящую очередь приложения.
4. Подключение к каждой обычной ловушке: Modbus read, S7 handshake, HTTP GET, Memcached GET, чтение TCP-баннеров и отправка текста, Redis AUTH/PING/SET/GET, SSH-вход и команды `whoami; pwd; uname -a; ls -la`. Пароль SSH/Redis генерируется для новых приманок отдельно от пароля оператора.
5. Прямое подключение к Шлюзу: `status` вызывает внутренний health-сервис.
6. Два запроса к Порталу: **Alice → alice**, затем JSON с числовым `score` переходит в Шлюз. `score=25` вызывает `jury.gateway.backup` (high); `score=90` — `jury.gateway.high_risk` (critical). Одинаковый `run` связывает события двух ловушек. В терминале видны результаты трёх веток Портала.
7. Сломанный JSON и неизвестная операция возвращают 422.

Для протокольных запросов проверяются ответы, сохранённые события **именно от нового соединения**, затем доставка этих же event ID через `/api/stream` с протоколом `dashboard-stream.v1`. Для цепочки дополнительно проверяются переданные значения и выбранная ветка. Это проверка транспорта, используемого фронтендом; отрисовку браузера жюри наблюдает самостоятельно.

## Перед выступлением

```powershell
.\start.cmd -Preflight
```

Этот режим входит в аккаунт, проверяет каталог, доступ к конструктору, занятые порты и готовность WebSocket. Ловушки, профили и схемы не создаёт. Доступность ещё не созданных слушателей он проверить не может.

Все десять ловушек требуют ресурсов сервера и включённого автоматического развёртывания. Первое создание образов/контейнеров может занять время. Скрипт ждёт каждую ловушку до четырёх минут и печатает промежуточное ожидание. Для показа заранее проверьте наличие образов Conpot/Dionaea/SSH на сервере.

По умолчанию слушатели доступны на домене сайта. Если опубликованные порты находятся на другом узле:

```powershell
.\start.cmd -HostAddress 192.0.2.10 -PortBase 35000
```

Адрес выше — пример, замените его адресом своего узла. Начальный диапазон по умолчанию — 34000–34019; занятые порты профилей и черновиков своей организации пропускаются диапазонами по 20. Используются 12 портов в пределах первых 14: восемь обычных и четыре HTTP-слушателя на двух ловушках; ещё два пропущены. Firewall должен пропускать используемые TCP-порты. Порты других организаций и посторонних процессов через API не видны: при конфликте сценарий остановится.

Сайт использует самоподписанный сертификат. В комплекте его публичный сертификат; проверка TLS и имени сервера включена. Для другого сайта с собственным CA используйте Python напрямую с `--ca`:

```powershell
python demo.py --site https://your-honeyforge.example --ca your-ca.pem
```

Для сайта с общедоверенным сертификатом `--ca` не нужен.

## После показа и при ошибке

Ловушки **остаются работать**. Автоматического удаления нет. Каждый запуск создаёт новый набор с уникальной меткой и новым свободным диапазоном портов. ID профилей, схем и ловушек, результаты проверок и event ID записываются в `runs/*.json` после каждого завершённого действия; секретов в отчёте нет. `passed=true` устанавливается только после всех проверок. Флаг `frontend_ws=true` означает получение указанных event ID через канал фронтенда.

При ошибке сценарий заканчивается с ненулевым кодом; уже созданные ресурсы остаются в панели. Посмотрите отчёт, состояние ловушки и доступность её порта. Автоматического продолжения прерванного запуска нет: новый запуск создаст новый набор. После выступления остановите и удалите ненужные ресурсы по метке запуска через панель.

## Запуск без Windows-обёртки

```sh
python -m pip install -r requirements.txt
python demo.py
```

`--no-browser` отключает открытие браузера. Логин и пароль через аргументы или файлы не принимаются.

## Проверки разработчика

В репозитории из его корня:

```sh
python -m pip install -r scripts/jury_demo/requirements-dev.txt
python -m unittest discover -s scripts/jury_demo -v
```

Проверяются графы, набор и диапазоны портов, скрытие ошибок API, отказ зрителю, разбор RESP, корреляция событий, доставка точных event ID, компиляция настоящим конструктором, соответствие профилей опубликованным схемам и выполнение обеих веток связанными интерпретаторами. В отдельном архиве проверки компилятора/интерпретатора пропускаются: для них нужны исходники сервера.
